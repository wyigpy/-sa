# 星课it-算法面试通关
获课：xingkeit.top/18825/算法面试通关


栈队列哈希表精讲：高频面试题，理清边界条件与代码实现
栈、队列、哈希表是面试里出现频率最高的三类数据结构。题目本身往往不难，真正拉开差距的是边界条件和实现细节：空结构怎么处理、重复元素怎么算、扩容和删除的时机、指针和索引的越界。下面按数据结构拆解高频题型的解题思路和易错点。

一、栈：后进先出的“顺序陷阱”

栈的核心是 LIFO，高频题集中在括号匹配、表达式求值、单调栈和递归模拟四类。

括号匹配的边界条件是重点。空字符串算不算合法？只有一个右括号时能否正确返回不匹配？嵌套层次很深时会不会栈溢出？实现上遇到左括号入栈，遇到右括号先判空再比对栈顶，遍历结束后栈必须为空才算合法。三个检查点缺一不可：入栈前、出栈前、遍历后。

表达式求值（逆波兰式或中缀转后缀）的坑在运算符优先级和负数处理。遇到减号要区分它是二元运算符还是一元负号；多位数要连续读取而不是逐字符计算；除零和溢出要显式处理。用两个栈分别存数字和运算符时，每次弹栈前都要判空，否则非法表达式会直接崩溃。

单调栈是近年高频。典型题是“下一个更大元素”和“柱状图中最大矩形”。核心维护一个单调递减或递增的栈，每个元素最多入栈出栈一次，复杂度线性。边界条件在于：栈为空时当前元素没有“前一个更大值”；遍历结束后栈里剩余元素没有“下一个更大值”，要按题意补默认值。容易错的是相等元素——严格单调还是非严格单调，取决于题目是否允许相等值作为答案。

用栈模拟递归（如二叉树非递归遍历）时，要注意入栈顺序和访问顺序相反。前序遍历先压右再压左，中序需要配合指针一路压左，后序可以用双栈或标记法。空节点不入栈是基本纪律。

二、队列：先进先出与“循环”的边界

队列的高频题包括用栈实现队列、滑动窗口最大值、层序遍历和任务调度。

用两个栈实现队列，关键是“出队栈为空时再把入队栈全部倒过去”，且只在出队栈空时倒，否则顺序会乱。边界是连续出队和连续入队交替时，要保证倒栈只发生一次。

循环队列的边界是面试经典陷阱。用数组实现时，队空和队满的判断不能都用 head==tail，否则无法区分。常用方案是牺牲一个空间：队满条件是 (tail+1)%capacity==head；或者额外维护 size 变量。入队前判满、出队前判空，取模运算在 head 和 tail 为负时要特别小心。

滑动窗口最大值用单调双端队列：队头维持当前窗口最大值，新元素入队前从队尾弹出所有比它小的元素，窗口左边界移动时如果队头下标过期就弹出。边界在于窗口大小为一、数组为空、窗口大于数组长度这几种情况，都要单独验证。

层序遍历（BFS）的易错点是“按层分组”。每轮先记录当前队列长度，只处理这么多节点，新入队的子节点留到下一轮。空树直接返回空结果，不要返回含空列表的结果。

三、哈希表：冲突、扩容与“键”的设计

哈希表的高频题包括两数之和、字母异位词分组、最长连续序列、LRU 缓存。题目简单，但考察的是对哈希本质的理解。

两数之和的边界：数组有重复元素时，要先查再存还是先存再查？正确顺序是遍历时先查 target 减当前值是否在表中，不在再把当前值存入。这样避免同一个元素用两次。返回下标还是返回值，要看清题意。

字母异位词分组的核心是“键的设计”。排序后的字符串做键最直观，但复杂度带排序开销；用字符计数数组转成字符串做键更高效。键必须满足“互为异位词则键相等，否则键不等”，这是分组类题目的通用原则。

最长连续序列要求线性复杂度，做法是把所有数放进集合，只从“没有前驱的数”开始向上数。边界是空数组、全部重复、负数序列。判断前驱时用集合查找而不是排序，才能保证整体线性。

LRU 缓存是哈希表加双向链表的组合题。哈希表存键到节点的映射，双向链表维护访问顺序。易错点有三：访问命中后要把节点移到链表头；插入新键时若容量已满要删除链表尾节点并同步删哈希表；自己实现双向链表时头尾哨兵节点的指针要初始化正确，删除和插入的四个指针赋值顺序不能错。

哈希表的通用边界：键为 null 是否允许（取决于实现）；哈希冲突严重时性能退化，面试中要能说出负载因子和扩容策略；遍历哈希表时不能边遍历边修改结构，否则行为未定义，需要先收集再删除。

四、三类结构的组合与选型

面试里经常出现组合题：用栈实现队列、用队列实现栈、设计带 min 函数的栈（辅助栈同步或不同步）、设计 LFU（哈希加频次链表）。选型判断很简单：需要后进先出用栈，需要先进先出或层序用队列，需要 O(1) 查找用哈希表。组合题的关键是明确每个结构的职责边界，不要用一个结构硬扛两种语义。

最后给一条通用纪律：每道题写完，先用空输入、单元素、全相同元素、极端顺序这四组用例过一遍，再检查指针和索引的越界。数据结构题的正确率，八成取决于边界条件是否想全，而不是主逻辑写得多漂亮。
